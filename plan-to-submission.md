## 2. Rules for all remaining work

1. **The method and the schemas stay frozen.** Do not change any setting, threshold or question because of a test result. Do not rerun anything "to see whether it gets better".
2. **New analyses are additions, not replacements.** Each must be declared (in this plan or in `notes/`) before it is run. Report it whatever it shows.
3. **No hand-typed numbers in the paper.** Every new result needs a key in `make_paper_assets.py`.
4. **Simulated results never go into the paper** (`generated_sim` is for layout checks only).
5. **The test set is not used for any decision.** Pilots and tuning use the pool only.

### WP6. Preparing for the revision

Prepare answers in advance (`notes/reviewer-faq.md`) to the questions most likely to come:

- **Closed model, not reproducible.** Answer: WP2.1, the stored responses, the method is defined for the whole class of models, and the adapter.
- **The gate automates little.** Answer: the bound is valid and conservative; the paper explains each refusal (label noise, policy gap, too few critical cases); WP2.2 quantifies the requirement.
- **Label noise in CFPB.** Answer: the audit (LLM-assisted plus the WP1 human check) and the EMSCAD contrast.
- **The method was revised after seeing results.** Answer: one documented, uniform revision, frozen before reporting; the v1 results are in the repository.
- **Fraud table with 49 rules is not readable.** Answer: the fidelity–complexity curve (about ten rules give almost the same fidelity), the FIRST-policy size, and that rule size is a process-owner choice.
- **Why not a stronger text classifier (fine-tuned transformer)?** Answer: the comparison concerns auditable logic; TF-IDF+LR is the standard transparent-input baseline. If a reviewer insists, add a fine-tuned DistilBERT as an upper bound.

## 5. Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Human check disagrees strongly with the LLM audit (κ < 0.6) | Medium | Report it as found. The gate-refusal argument for routing then rests on fewer cases; soften the wording in RQ3 and Limitations. |
| TypeSafe terms forbid publishing the responses | Low–medium | Publish aggregates, IDs and code. Reproduction then goes through the adapter (WP2.1). |
| Open-model reproduction gives very different results | Medium | That is a finding: report it and discuss model dependence. The method's guarantees hold regardless. |
| The `jev-1.13.0` version is withdrawn before revision | Medium | All responses are cached. New analyses during revision use the cache; any new queries are flagged as a different model version. |
| Desk rejection for scope ("method paper about one commercial model") | Low–medium | The cover letter stresses the DMN/BPM contribution, the open adapter and the general gate pattern; WP2.1 helps. |
| Reviewers ask for a larger fraud calibration set | Medium | WP2.2 shows the requirement explicitly. A new split would be a pre-declared extension, not a change of the frozen protocol. |
